## Быстрый запуск

Нужны Node.js 22.12+ и npm. Для окружения курса можно использовать Node.js
24.19.0. Откройте в VS Code именно папку `coursework`, содержащую этот README и
`package.json`. В терминале PowerShell:

```powershell
npm.cmd install
npm.cmd run dev
```

В Git Bash команды аналогичные, можно писать `npm` вместо `npm.cmd`.

Откройте **http://127.0.0.1:3000**. Один запуск поднимает два отдельных
процесса: фронтенд Vite на порту 3000 и Express API на порту 8080. Остановить
оба процесса — Ctrl+C в этом терминале.

Учётная запись для проверки:

| Поле   | Значение         |
| ------ | ---------------- |
| Логин  | `egor`           |
| Пароль | `GadgetHub2026!` |

Сначала войдите через кнопку «Войти». Главная и логин доступны без входа;
каталог и корзина требуют авторизации. Открывать HTML двойным щелчком или через
Live Server не нужно: приложению необходимы Vite, Vue и работающий API.

Для раздельного запуска в двух терминалах из этой же папки:

```bash
npm run dev:server
```

```bash
npm run dev:client
```

Если 3000 или 8080 заняты, остановите предыдущий экземпляр сервера. Проект не
переключается незаметно на другой порт. Используйте один адрес `127.0.0.1:3000`
во время проверки: localStorage и cookie привязаны к адресу.

## Сборка и тесты

```bash
npm test
npm run build
npm start
```

`npm run typecheck` проверяет фронтенд, шаблоны Vue и сервер в strict mode.
`build` проверяет типы, собирает фронтенд в `dist` и компилирует сервер в
`dist-server`. `start` запускает просмотр собранного сайта на 3000 и API
на 8080. Установка зависимостей требует интернета; после установки все
изображения, шрифты и данные доступны локально.

Тесты проверяют API, авторизацию, серверную валидацию, расчёт суммы, повторную
отправку заказа, параллельную запись, сохранение после перезапуска, фильтрацию,
сортировку и пагинацию. Тестовые заказы пишутся в отдельную временную папку,
пользовательская история магазина не затрагивается.

## Что реализовано

- Главная: баннер из макета, две закольцованные карусели, преимущества,
  контакты.
- Одинаковые шапка и подвал, активный пункт меню, счётчик единиц в корзине.
- Вход с проверкой обязательных полей и окном ошибки, выход, серверная сессия.
- Защищённые маршруты каталога и корзины; защищённые API товаров и заказов.
- Каталог из 41 товара, три колонки и девять товаров на странице — пять страниц.
- Фильтры цены, типа и цвета; применение кнопкой «Показать», сброс и отсутствие
  результатов. Пустая группа чекбоксов эквивалентна выбору всех значений.
- Сортировка по новизне, популярности и цене; оба направления сортировки.
- Модальная карточка товара: фото, описание, характеристики, цена, рейтинг,
  лейблы и управление количеством; закрытие крестиком, Esc и по фону.
- Корзина: количество, суммы строк и общий итог, выбор позиций, подтверждение
  одиночного и группового удаления.
- Оформление: обязательный телефон, необязательная почта, самовывоз/доставка,
  условно обязательный адрес, выбор оплаты и упаковки.
- Подтверждение оформления, очистка корзины после успеха, история заказов.
- Русские тексты, рубли, локальный Rubik и десктопная фиксированная сетка.

## Архитектура

```text
coursework/
├── client/
│   ├── index.html
│   ├── public/assets/       # Фото, баннер, оформление входа, иконки, Rubik
│   └── src/
│       ├── App.vue          # Оболочка приложения и RouterView
│       ├── api.ts           # Запросы, ошибки, форматирование суммы
│       ├── store.ts         # Реактивное состояние, сессия и корзина
│       ├── catalog.ts       # Чистые функции фильтрации/сортировки/пагинации
│       ├── router.ts        # Vue Router и защита маршрутов
│       ├── components/      # Карточки, диалоги, поля, шапка и подвал
│       ├── pages/           # Home, Login, Catalog, Cart
│       └── styles.css
├── server/
│   ├── index.ts            # Запуск Express на 8080
│   ├── app.ts               # API, сессии и оформление
│   ├── validation.ts        # Проверка данных во время выполнения
│   ├── store.ts            # Последовательная асинхронная запись заказов
│   └── data/
│       ├── goods.json       # Каталог
│       └── orders.json      # Создаётся автоматически при первом заказе
├── shared/types.ts          # Общие типы клиента и сервера
├── scripts/dev.mjs          # Запуск и остановка двух процессов
├── tests/                   # Node.js test runner
├── docs/                    # API и соответствие требованиям
├── vite.config.ts
└── package.json
```

Vue Router отвечает за адреса `/`, `/login`, `/catalog`, `/cart`. Вкладка
истории имеет адрес `/cart?tab=history`. Реактивное хранилище Vue передаёт
сессию, корзину и обработчики компонентам. Корзина хранится под ключом
`gadget-hub.cart.demo`; при выходе содержимое сохраняется для следующего входа
того же пользователя. Данные других сайтов не очищаются.

Запросы фронтенда идут на `/api`; Vite перенаправляет их на отдельный
сервер 8080. Это позволяет обойтись без CORS и хранить сессию в HttpOnly cookie.
Cookie действует восемь часов. Сессии находятся в памяти API: после перезапуска
бэкенда нужно снова войти, но история заказов и корзина сохраняются.

Сервер не доверяет присланной цене: проверяет товары и количество и вычисляет
сумму по `goods.json`. Заказ записывается сначала во временный файл, затем
атомарно заменяет основной. Очередь записи исключает потерю параллельных
заказов. `requestId` защищает от дубликатов при повторной отправке одного
оформления. При ошибке API корзина остаётся на месте.

## Данные и макеты

Источники: `Курсовой проект.pdf`, `Gadget Hub.fig`, `Gadget Hub - pages.pdf`,
`Gadget Hub - UI kit.pdf`, `Gadget Hub Assets.zip`.

Шрифт Rubik, изображения товаров и социальные иконки взяты из предоставленных
материалов. Баннер и декоративные иллюстрации входа извлечены из PDF-макета; сам
интерфейс форм, карточек и страниц реализован HTML/CSS/Vue. Лицензия Rubik
находится в `client/public/assets/fonts/OFL.txt`.

Предоставленный `goods.json` содержит только ID и названия 32 товаров. У товара
28 исправлена неэкранированная кавычка в обозначении дюймов. Каталог дополнен
девятью товарами из макета страниц с соответствующими изображениями. Для данных,
отсутствующих в архиве, добавлены учебные цены, рейтинги, даты, категории,
описания и характеристики. Это демонстрационные данные, не предложение реального
магазина. Значения видимых первых товаров и баннера взяты из макета. Внешние
ресурсы не загружаются во время работы сайта.

При противоречиях макета и текста приоритет дан ТЗ: например, телефон
обязателен, почта необязательна; общая сумма корзины считается по всем
фактическим позициям. Адаптация под мобильные устройства по ТЗ не требуется:
минимальная ширина страницы 1280 px, контент 1240 px.

## Настройки и данные сервера

Необязательные переменные окружения API:

| Переменная      | По умолчанию              | Назначение                                     |
| --------------- | ------------------------- | ---------------------------------------------- |
| `DEMO_LOGIN`    | `egor`                    | Логин единственного пользователя               |
| `DEMO_PASSWORD` | `GadgetHub2026!`          | Пароль пользователя                            |
| `ORDERS_FILE`   | `server/data/orders.json` | Путь для сохранения заказов                    |
| `API_PORT`      | `8080`                    | Порт API; при изменении поправьте proxy в Vite |

Пароль проверяется через scrypt, сессионный токен создаётся криптографическим
генератором. Учебная учётная запись одна, как разрешает ТЗ. Платёжный шлюз не
подключён: способ оплаты сохраняется в заказе, данные банковской карты не
запрашиваются.

## Стек и TypeScript

Все Vue-компоненты используют `<script setup lang="ts">`. Общие типы товаров,
пользователей, корзины, покупателя и заказа находятся в `shared/types.ts`.
`client/src/store.ts` содержит реактивное состояние и операции магазина;
`client/src/router.ts` — маршруты и проверку доступа. `server/validation.ts`
проверяет входные данные API во время выполнения.

`tsconfig.json` отвечает за клиент и Vue-компоненты, `tsconfig.server.json` — за
Node.js-сервер. Оба включают strict mode. В разработке сервер запускается через
`tsx`; после `npm run build` команда `npm start` запускает скомпилированный
сервер и собранный сайт.

Исходники старой версии в новую поставку не входят. При замене старого проекта
распакуйте архив в новую папку, чтобы не смешивать файлы.
